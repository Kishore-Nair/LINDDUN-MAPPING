# CVE–LINDDUN: a privacy-threat-labelled CVE corpus

**280,694 CVEs (1999–2025), 174,294 labelled with LINDDUN privacy threat
classes (62.1%).** Built 2026-11-11.

Each row is one published CVE with its NVD scoring, description, CWE, and a
LINDDUN privacy threat label derived from that CWE through a documented,
re-runnable mapping chain.

---

## Why this exists

LINDDUN is a design-level privacy threat framework; CWE is an
implementation-level weakness taxonomy. No authoritative mapping between
them has been published. This dataset is an attempt at one, applied at
scale to real vulnerability data, with every label traceable to the rule
that produced it.

---

## How a label is produced

```
CVE --(NVD)--> CWE --(hop 1)--> MITRE category --(hop 2)--> LINDDUN
                                                      |
                                              CWE-level override
```

| Step | Table | Origin |
|---|---|---|
| hop 1 | `cwe_category_map.csv` | generated by `03c` from `cwe_linddun_mapping main.csv` |
| hop 1 additions | `cwe_category_additions.csv` | CWEs absent from the local extract, added with MITRE justification |
| hop 2 | `category_id_to_linddun.csv` | generated by `03e` from the curated use/misuse table |
| exclusions | `excluded_abstract_cwes.csv` | 6 MITRE-discouraged abstract CWEs |
| refinement | `cwe_linddun_overrides.csv` | 14 CWE-level overrides + 4 reviewed-unchanged |

**The label is a pure function of `cwe_id`.** Verified directly: grouping
the corpus by CWE yields exactly one label-set per CWE. The description
text played no part in producing it. This matters for how the dataset may
be used — see Limitations.

## Columns (28)

**Source** `cve_id`, `description`, `severity`, `cvss_v2/v3/v4`, `cwe_id_raw`
**Derived** `cwe_id` (null when not a real CWE), `cwe_valid`, `year`,
`cvss_score` + `cvss_version` (coalesced newest-first; v2 and v3 are
different scales, so the version is recorded rather than silently merged —
99.3% coverage: v3 198,604 / v2 72,517 / v4 7,469)
**Chain** `linddun_status`, `cwe_category_ids`, `cwe_categories`,
`linddun_categories_base` (category-inherited), `linddun_categories`
(after override), `linddun_primary`, `linddun_override_applied`,
`linddun_override_rationale`, `n_linddun`
**Multi-label** seven `ld_*` booleans
**Split** `split` — stratified 70/10/20, seed 42

## Validation

There is no ground truth, so this is **not** validated by accuracy.

**Anchor tests — 17/17 passing** (`15_anchor_tests.py`). These check CWEs
whose names state the privacy effect outright, leaving no room for
judgement: if CWE-532 "Insertion of Sensitive Information into Log File"
lacks Data Disclosure, the mapping contradicts MITRE's own title.

The suite caught three real defects, all now fixed:

| CWE | Was | Problem | Fix |
|---|---|---|---|
| CWE-532 | `Non-repudiation` | inherited from Audit/Logging Errors — assigned by *mechanism*, missed the *effect* | added Data Disclosure |
| CWE-312 | `Detectability;Identifiability;Linkability` | inherited from Cryptographic Issues, no Data Disclosure | added DD, dropped Detectability |
| CWE-798 | unmapped | absent from the 28-category extract | added to Authentication Errors |

**Sensitivity: 26.7%** of labelled rows (46,490) change depending on 14
override decisions. The mapping is not robust to those judgements and
they must be reported alongside any result derived from it.

## Limitations — read before using

1. **Do not train description → LINDDUN on this.** Labels derive from
   `cwe_id`, and NVD descriptions routinely name the weakness, so a text
   model would recover the lookup table through a leak rather than learn
   anything. Descriptions are for *explanation*, not supervision.
2. **No expert validation yet.** The defensible next step is an
   inter-rater agreement study: ~300 stratified CVEs, 2–3 raters blind to
   the pipeline, Krippendorff's alpha, reporting rater-vs-rater agreement
   as the ceiling. Until then, "validated" means internally consistent.
3. **Non-repudiation rests on one CWE.** CWE-532 is 57% of the class.
4. **Temporal drift tracks NVD practice, not privacy.** Identifiability
   falls from 21.4% of labelled CVEs in 2015 to 9.4% in 2025 as NVD moved
   toward more specific CWEs. Do not read this as a trend in privacy risk.
5. **The source category extract is partial** — 28 MITRE categories
   against the 40 the original methodology used, so coverage here is not
   comparable to the published C3-VULMAP figures.
6. **CVSS is a weak proxy for privacy severity.** Median score by primary
   class spans only 6.0–7.5. CVSS measures security impact; LINDDUN does
   not.

## Reproducing

```bash
cd "FINAL YEAR PROJ/c3_vulmap_v2" && python3 15_anchor_tests.py   # must pass
cd "FINAL YEAR PROJ/cve_linddun"  && python3 build_cve_linddun.py
```

Deterministic — seed 42, no network, no model. Explain any CWE with:

```bash
cd "FINAL YEAR PROJ/c3_vulmap_v2" && python3 14_explain_linddun.py --cwe CWE-532
```
